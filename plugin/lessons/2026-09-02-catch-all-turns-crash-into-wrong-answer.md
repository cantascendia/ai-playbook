# Learned Rule: リクエストハンドラの catch-all は、例外を「もっともらしい間違った答え」に変える

**学到的教训**: ローカル確認サーバーが日本語の行き先で 301 の代わりに **404** を返していた。
規則は表にあり、突き合わせも一致していたのに 404。原因は

```js
res.writeHead(301, { location: 'https://…/アセット-10x1-1.png' })
```

—— Node は Latin-1 の外の文字をヘッダ値に入れると `ERR_INVALID_CHAR` を投げる。
それがハンドラ全体を包む `catch { 404 を返す }` に落ちていた。

**表示されたのは「404」だけ。**「規則が無い」のか「規則はあるが送信で落ちた」のか
区別が付かず、本番の不具合と見分けられないまま 30 分溶かした。
同じ日、同じファイルの読み込みキャッシュにも競合があり（値だけ覚えて mtime を
先に更新 → 読み込み中の要求が空の表で答える）、**毎回ちょうど 4 本**落ちていた。
一定数なので「規則が抜けている」に見えた。

## 触发场景

- HTTP ハンドラ / ジョブワーカーを `try { … } catch { 既定の答えを返す }` で包んでいる
- 既定の答えが**正当なドメインの値**（404 / 空配列 / null / 0 件）
- ヘッダ・ファイル名・SQL・JSON に**非 ASCII や制御文字**が入りうる
- 非同期の読み込みを「値」でキャッシュし、フラグを await の前に立てている

## 应该怎么做

1. **catch-all は必ず握った例外を出す。** 少なくとも 1 行:
   ```js
   } catch (e) {
     console.error('[500 相当]', req.url, e)   // ← これが無いと診断不能
     res.writeHead(404, …)
   ```
   「既定の答え」を返すのは構わない。**黙るのが悪い。**
2. **調べるときは、まず catch を外すか例外を出す。**
   「入力は正しい」を何度も確かめる前に、例外の有無を先に見る。
3. **ヘッダに入れる値は必ず符号化する。** URL なら path 部分だけ:
   ```js
   const x = new URL(u); x.origin + encPath(decodeURI(x.pathname)) + x.search
   ```
4. **非同期キャッシュは「約束」ごと覚える**（値＋先出しフラグは競合する）:
   ```js
   if (m !== mtime) { mtime = m; loading = readFile(f).then(t => { VALUE = JSON.parse(t) }) }
   if (loading) await loading
   ```
5. **「毎回ちょうど N 本落ちる」は競合のサイン。** 内容ではなくタイミングを疑う。

## 避免什么

- ❌ `catch {}` / `catch { return 既定値 }` を**ログ無し**で書く
- ❌ 404 や空配列を見て「データが無い」と診断する（例外かもしれない）
- ❌ 入力側（パス・台帳・突き合わせ）を何度も確かめて、出力側（送信）を見ない
- ❌ 非同期読み込みで、await の**前**に「読んだ」フラグを立てる
